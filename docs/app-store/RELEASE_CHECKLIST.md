## Уже подготовлено в проекте

- Правовые тексты EN/RU/UK: условия, конфиденциальность, программа авторов, источники и поддержка; доступны в настройках.
- Метаданные EN/RU/UK в metadata.json; версия 1.0.0, build 3.
- Бесплатный публичный каталог: 50 блюд, включая 18 завтраков; полный курс содержит 150 блюд, без необходимости входа. Закрытая пилотная библиотека не загружается в Release.
- Дневник, CSV, история веса и графики. Запланированная еда не становится фактически съеденной автоматически.
- В Release личное состояние сохраняется в защищённом локальном файле и исключается из резервного копирования; личная CloudKit-синхронизация отключена. Старые облачные данные не удаляются автоматически.
- Privacy manifest для UserDefaults, без tracking domains. Стандартный HTTPS; декларация ITSAppUsesNonExemptEncryption=false должна быть подтверждена итоговой проверкой экспортного контроля.

## App Privacy

Инвентаризация основана на коде, а не на одном manifest:

- Возраст, рост, вес, аллергии, питание, дневник и запасы в Release обрабатываются на устройстве; не отправляются автоматически разработчику, авторам, CloudKit или AI.
- Каталог запрашивается по HTTPS. Сервер видит IP и технический контекст соединения. В текущем nginx access log отключён; error logs, reverse proxy, hosting/provider retention нужно проверить отдельно.
- Подключены Google Mobile Ads и UMP. Запросы рекламы неперсонализированные, без профиля, дневника, веса, аллергий, целей и выбранных блюд. Межприложенческое отслеживание не запрашивается. Privacy Report и App Privacy должны учитывать фактический сбор данных SDK. Автоматической AI-передачи нет.
- CSV передаётся только получателю, которого выбрал пользователь. Возможность отправить файл в GPT/Claude не означает автоматическую интеграцию.
- Не выставлять «Data Not Collected» до проверки реального логирования. Если IP/диагностика сохраняются и доступны оператору, заполнить соответствующие категории, цели, связь с пользователем и retention по фактическому поведению.
- Проверить архивную Privacy Report в Xcode и ответы App Store Connect. HealthKit не используется.

[App Privacy](https://developer.apple.com/app-store/app-privacy-details/) и [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) — первичные документы для окончательной проверки.

## Проверки кандидата

Для тестов Release, использующих существующие фикстуры каталога, передать `ENABLE_TESTABILITY=YES SWIFT_ACTIVE_COMPILATION_CONDITIONS='$(inherited) LAD_TESTING'`. Флаг LAD_TESTING открывает только внутренний помощник фикстур: он не включает DEBUG, доступ по ключам или CloudKit. Итоговый архив собирается без LAD_TESTING и без DEBUG. Запуски тестов на одном симуляторе выполнять последовательно.

- [ ] Воспроизводимые Debug-тесты и отдельная Release-сборка/архив, без DEBUG launch arguments.
- [ ] Подписанная Release-сборка на реальном устройстве: чистая установка, обновление с пилота, офлайн, ошибки сети, защищённое хранилище после блокировки, повторный запуск без потери записей.
- [ ] Ни один сохранённый ключ не разблокирует закрытые рецепты или paid course в Release; публичное API анонимно возвращает только разрешённый каталог.
- [ ] Проверить миграцию старых данных на копии, не стирать личный телефон. Прежние сторонние/iCloud-копии не удаляются приложением автоматически.
- [ ] График: 0/1/много точек, периоды, отдельные люди, запись, редактирование, удаление, backdating, CSV, большие шрифты и VoiceOver.
- [ ] EN/RU/UK, маленький iPhone, светлая/тёмная тема, все документы и ссылки; нет смешения языков.
- [ ] Уведомления: отказ, включение/выключение, без блюд/калорий на lock screen.
- [ ] Экспорт: выбор получателя и отмена; нет формул из текстовых CSV-полей и автоматической отправки личных данных.
- [ ] Скриншоты реальной Release-версии в требуемом App Store Connect размере; только явно демонстрационные данные. Debug-скриншоты не должны обещать скрытые Release-функции.
- [ ] Полная иконка 1024×1024 без alpha; app thinning/signing/Validate App в Organizer, release notes и review contact.
- [ ] TestFlight beta review при использовании внешних тестировщиков; тестирование полученной через TestFlight сборки.
- [ ] После ручного подтверждения всех пунктов — отправка на App Review. Одобрение не гарантируется.

## Платные авторские курсы: следующий этап, не часть первого checkout

Лад может дать авторам удобный способ продавать курсы и получать вознаграждение; пользователям — составлять и учитывать рацион по структурированным правилам. Для запуска нужны отдельные изменения:

- Договор: права, территории, переводы/AI, цены, формула доли, база после согласованных удержаний, валюта, порог и расписание выплат, налоги, refunds/chargebacks, отчёты, прекращение и сохранение купленного доступа.
- Соответствующая требованиям Apple система покупки цифрового контента; для обычного in-app checkout — StoreKit, проверка транзакций, restore, серверные права и отзыв при возврате. Внешние ссылки/покупки требуют отдельного анализа допустимости для конкретного рынка и entitlement, не подменяются ключом доступа.
- Учёт продаж и проверяемые отчёты, безопасный процесс выплат авторам. Доход и процент комиссии не обещать без договора.
- Подтверждение авторов/прав, редакционная проверка, модерация и жалобы, политика снятия спорного курса; public author upload пока отсутствует.
- Авторы не получают личные данные здоровья покупателей только потому, что пользователь подключил курс.

До выполнения этого раздела платные курсы и автоматические выплаты не рекламируются как работающая функция.
