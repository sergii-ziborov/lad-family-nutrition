# Лад — одна кухня, разные порции

Нативный SwiftUI-прототип семейного планировщика питания для iPhone. Открытые демо-рецепты доступны офлайн; опубликованные программы и новые блюда загружаются из отдельного каталога. Закрытые материалы требуют авторизации. Исходники приложения доступны публично, но **не распространяются по open-source лицензии** — см. [LICENSE](LICENSE).

В прототипе работают семь дней меню, участники каждого приёма пищи, ручные порции, отметки съеденного, личное избранное и реакции на блюда. «Сегодня не хочу» предлагает замену для конкретного приёма пищи; меню и покупки меняются после подтверждения. Раздел «Каталог» содержит курсы и рецепты: опубликованные бесплатные программы доступны без ключа, закрытые — только с доступом. Выбранные курсы становятся источником блюд для нового подбора; уже составленная неделя не меняется автоматически. Девять открытых демо-рецептов и две бесплатные демонстрационные подборки лежат в [`public-recipes.json`](Lad/public-recipes.json) как офлайн-старт. Раздел «Продукты» учитывает известные и неизвестные остатки, сроки и недостающие ингредиенты, поддерживает поиск по синонимам и автоподгрузку списка. Личные настройки семьи хранятся на iPhone.

## Запуск

Откройте `Lad.xcodeproj` в Xcode, выберите схему `Lad` и iPhone Simulator, затем Run. Для физического iPhone требуется собственная команда разработчика и активный профиль подписи в Xcode. Исходный `project.yml` можно пересоздать через `xcodegen generate`; проект Xcode также сохранён в репозитории.

В локальном клоне включите проверку перед коммитом: `git config core.hooksPath .githooks`. Она запускает iOS-тесты и не допускает серверные/закрытые файлы в публичный индекс. Сервер и его тесты находятся в отдельной закрытой рабочей области.

Для проверки в терминале:

```sh
xcodebuild -project Lad.xcodeproj -scheme Lad -configuration Debug -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Lad.xcodeproj -scheme Lad -destination 'platform=iOS Simulator,name=iPhone 13 mini' CODE_SIGNING_ALLOWED=NO test
```

## Каталог и закрытая библиотека

Раздел «Курсы» принимает HTTPS-адрес каталога; бесплатные опубликованные программы доступны без ключа. Кнопка «Закрытая библиотека» на экране рецептов принимает тот же адрес и личный ключ. Ключ хранится в iOS Keychain. Если каталог отключён, запланированный закрытый рецепт **не подменяется** похожим открытым: приложение показывает недоступность и неполноту покупок.

Серверный код, база, закрытые рецепты, семейные данные, изображения, ключи и импортные материалы ведутся отдельно от публичного репозитория приложения. Публичный JSON содержит только демонстрационные рецепты. Текущий общий ключ доступа — пилотная схема, не система оплаты или индивидуальных прав на программы. Черновики без проверенных критичных данных не должны попадать в автоматический рацион.

## Границы и план

Это не готовый App Store-релиз: цифры питания, состав и технология девяти демо-рецептов не валидированы; детские, медицинские и аллергенные сценарии требуют профессиональной проверки. Калорийность служит только приблизительным сравнением; жиры, углеводы и микронутриенты без источника отображаются как неизвестные, а не нулевые. Никаких рекомендаций по снижению веса или приёму БАДов приложение не выдаёт.

Фотографии открытых демонстрационных блюд и иконка созданы для проекта; [запросы для части снимков](docs/IMAGEGEN.md) сохранены отдельно. Закрытые изображения не входят в публичный репозиторий. Переписывание текста и новая иллюстрация сами по себе не подтверждают права на публикацию исходного рецепта: перед коммерческим релизом нужен отдельный правовой и редакционный аудит.
